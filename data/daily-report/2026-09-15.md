### 5.2 Item 12, root-caused: it is a shallow clone, and a number this report has carried is wrong

Preflight failed this morning on `local main sane` and the consequent `git on main`, `tree clean`
passing — exception **(a)** — for what is now the 32nd day. I ran the single command it printed
(`git checkout -B main origin/main`) and re-ran: 10/10 green. Nothing was discarded.

Then I measured what the stale ref actually was, and the answer is not what this report has been
saying.

**The repository is a shallow clone.** `git rev-parse --is-shallow-repository` → `true`, and
`.git/shallow` carries **two** graft points:

| graft | dated | from |
|---|---|---|
| `795b80abb` — `chore(routine-log): merge pass 2026-09-05 (#771)` | 2026-09-05 | the clone this container made on **2026-09-09** |
| `33ddce672` — `chore(routine-log): review pass 2026-09-10 — no-op (#841)` | 2026-09-10 | a later fetch |

Each segment is exactly 50 commits deep, and they are **disjoint**:

```
$ git merge-base 786529ac4 origin/main
                                        ← empty. No common ancestor.
$ git rev-list --count 786529ac4..origin/main   → 50
$ git rev-list --count origin/main..786529ac4   → 50
```

**So the correction.** Yesterday's report, and #881 and #883 before it, described local `main` as
`786529ac4`, **"50 commits behind"**, and read the sequence 28 → 31 → 36 → 39 → 49 → 50 as a gap
that was widening day by day. That is wrong in a way worth stating plainly: local `main` is not
behind `origin/main` at all. The two share no ancestry, and the "50" on both sides is not a distance
— it is the **clone depth**, appearing twice. The "widening gap" was the graft boundary moving as
successive fetches truncated at successive points, not a snapshot drifting further out of date.

Yesterday's narrowing — *"the image or cache layer holding `.git` is five days stale"* — was the
right neighbourhood and the right instinct (the reflog does show this container's `.git` was created
2026-09-09 and reused today). But staleness is not the mechanism. **The mechanism is that a shallow
clone cannot express the ancestry the check asks about.**

This matters because it converts a 32-day-old mystery into a decision with two concrete options,
and it explains something the doc has found puzzling from the start — why the remedy is always `-B`
and never the fast-forward, and why exception (b)'s "`local main sane` PASSING" condition is so rare
here. `preflight.js:171` asks `sane = merge-base --is-ancestor main origin/main`. Against a
two-graft shallow clone that is **structurally unanswerable**, so it fails closed, every routine,
every day. It is not detecting a bad state. It is detecting a shallow clone.

Two ways to close it, and they are not equivalent — § 6 item **12**.
