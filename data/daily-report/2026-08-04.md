## Findings

### 1. Two routines and one report pass each did nothing for a full day — root cause now fixed

The 04:00, 05:00 and 12:00 passes all stopped at preflight. The review pass's own words are the
clearest statement of why the failure was *correct* behaviour:

> preflight's named remedy `git checkout main` moves the tree **BACKWARD onto a stale 5-day-old
> root**, which is exactly the stale-checkout hazard the check exists to catch.

> The container's local `main` ref is an UNRELATED history — distinct root commit (`4e176a7b` vs
> `4a9c0a10`), HEAD `0a732f15` (#276, 2026-07-30), 52/50 divergent commits, no merge-base.

All three refused the bad remedy and reported instead, which is why nothing was corrupted. #339 added
the `local main sane` check, named `git checkout -B main origin/main`, and the five routine docs now
authorise exactly that one recovery when `tree clean` has already passed.

**Verified working:** this pass hit the same failure at 19:37 UTC, ran the one authorised command,
re-ran preflight, and got **10/10 green**. First real use, first success. `daily-wave` and
`daily-merge` were never affected, so this was never a global outage.

### 2. `reports-close` did not run — a reader who reported an error got no reply today

Its slot passed 3½ hours ago and there is no shard, where 08-01, 08-02 and 08-03 all have one at
~16:05 UTC. It runs on the operator's Mac, so the likely cause is simply that the laptop was not

### 3. Generator defect the wave reported and deliberately did not fix

> `tools/template.js` (~line 233): `wordingDrift` is true whenever `schema.claimQuoteText` differs
> from `quotation.text`. But `toRecord` strips the trailing period from `displayQuote` and sets
> `claimQuoteText` on any difference — so **any record whose `quotationText` is the same sentence
> with a final period is classified as a wording drift on punctuation alone**. On a disputed record
> with no `creditedTo` that silently suppresses the ClaimReview claimant and flips the FAQ question.

It produced a real defect on a live page (`i-have-ways-of-making-money…`), which the wave worked
around in-record. The suggested central fix is to *"normalise trailing sentence punctuation on both
sides before deciding `wordingDrift`."* Not applied because a `wave-` branch touching `tools/` is a
scope escape.
