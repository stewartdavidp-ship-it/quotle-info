## Findings

### 1. The merge schedule is armed — yesterday's diagnosis was overtaken by events

`merge.yml` now has three lifetime runs, and two of them are `schedule`:

```
run #1  workflow_dispatch  2026-07-30T12:47:41Z  success   (the manual test)
run #2  schedule           2026-07-31T12:55:59Z  success   ← existed 49 min after yesterday's report
run #3  schedule           2026-08-01T12:01:49Z  success   ← today, merged #295
```

Yesterday's report stated *"`merge.yml` has **exactly one run in its lifetime**… **No `schedule` run
was ever created**"*, which was true when measured at 12:06 UTC and false by 12:56 UTC. **The trigger
was never the problem.** What is real is the delay: the cron is `0 11 * * *`, and the two runs
started at **12:55:59** and **12:01:49** UTC — 115 and 61 minutes late. GitHub defers scheduled runs
under load, and the practical effect is that the "07:00 merge pass" now lands at roughly 08:01 ET,
which is this report's own slot. Today the merge finished at 12:02:26 and this session started at
12:04. That margin is 94 seconds.

### 2. The queue cannot drain, and it is now growing

This is the finding that matters. The pass, by design, **merges one PR and stops** — every merge puts
every other branch `BEHIND` under `strict: true`, so their builds are invalid until rebuilt. Its own
output says so: `MERGE ONE, then re-run this.`

Today's run merged #295 and then classified all seven survivors `WAIT`:

> `merged: #295`
> `· WAIT: #286 #287 #288 #289 #292 #296 #297 — CI still running, they merge next pass`

and the report step immediately after gave the real reason:

> `WAIT  #286  reports/2026-07-30-close  mergeability not computed yet — re-run in a moment`
> (…the same line for all seven…)
> `=> 0 to merge, 0 needing a rebase+rebuild, 7 left alone`

GitHub invalidates `mergeable` on every open PR the instant something lands on `main` and recomputes
it asynchronously. The pass had just merged #295, so it re-read the queue during exactly the window
where every answer is `null`, saw nothing it could act on, and exited — **without rebuilding
anything.** An hour later the same gate correctly reports six `REBUILD`.

The rebuild half *does* work — yesterday's run rebuilt and pushed #286–#289 — but four later merges
put them behind again before the next pass. So the arithmetic is: **one trigger a day, at most one
merge (or one round of rebuilds) per trigger, against three or four new PRs a day.** 4 open
yesterday, 7 today. It only goes one way.

### 3. The wave rebuilt three pages it had already built — and one of them lost a fact

#295 and the still-open #287 contain **the same three quote slugs**:

```
data/quotes/we-are-what-we-pretend-to-be-so-we-must-be-careful-about.json
data/quotes/a-man-who-has-never-gone-to-school-may-steal-from-a-freight.json
data/quotes/a-thorough-knowledge-of-the-bible-is-worth-more-than-a.json
```

#287 built them on 07-31 and never merged, so `main`'s harvest queue still showed them unbuilt and
today's selector — deterministic on that queue — picked the same three. **A full night of research,
audit, skeptic and fix passes was spent re-deriving work that already existed.** This is the merge
backlog turning into duplicated spend, not just latency.

The re-run was not a waste in quality terms: #295 is genuinely the better record. It located the
**1899** original — *The Pocahontas Times*, 19 January 1899, read in a fetched primary via the LoC
API — and Mother Jones's 1903 version of the joke, aimed at Roosevelt himself. #287 had reached only
1945.

**But it dropped something #287 had found.** The live page now reads:

> the oldest attribution to him that anyone has produced is a **1952** book on public speaking

#287's research says otherwise, in its own words:

> Searching the Library of Congress newspaper archive pushed the earliest **attributed** printing back
> to **1 March 1945** — a Veterans of Foreign Wars newsletter, 26 years after Roosevelt died and seven
> years earlier than Wikiquote's citation. Two later printings (1950, 1963) were also located and read.

The merged record contains **zero** occurrences of "1945"; #287's contains twenty. So the published
page understates the earliest Roosevelt credit by seven years, against evidence this project produced
itself and has not merged. Nothing on the page is fabricated — it is a regression caused by the
duplicate build, and it is live.

### 6. Two waves, one constraint, two different conventions

Both waves hit the same wall — loc.gov's HTML viewer 403s every automated client while its JSON API

### 7. What #295 could not establish, and disclosed

- **The Vonnegut primary was not read.** *Mother Night* is in copyright, the IA scan lending-restricted.
  `verified` rests on Wikiquote's sourced section plus an independent Wikipedia article, "and **the page
  says so in its own provenance trail** rather than implying the book was opened." Flagged by the wave
  itself as "the wave's one judgement call."
- **`Locomotive Engineers Journal` vol. 33 (1899)** could not be obtained; cited as Wikiquote's, with
  the independently-fetched *Pocahontas Times* reprint carrying the claim instead.
- **`theodorerooseveltcenter.org` is outside this environment's egress allowlist** — the natural
  authority for "is this in his papers?" could not be consulted, so the negative rests on Wikiquote,
  Wikisource and Chronicling America.

## Needs a decision

1. **Make the merge pass drain the queue instead of shipping one PR a day.** Either run `merge.yml`
   hourly (a one-line cron change; it is idempotent and exits clean with nothing to do) or have
   `merge-run.js` loop — merge, wait for `mergeable` to recompute, rebuild the rest — inside one run.
   Without this the backlog only grows.

2. **Close #287 as superseded.** It is `DIRTY`, its three records are the same three that shipped in
   #295, and it is the only PR the gate refuses to touch. Closing it costs nothing but the 1945
   citation, which is item 3.

3. **Restore the 1 March 1945 VFW citation to the live freight-car page.** The published page says the
   oldest Roosevelt credit is 1952; #287 read a 1945 printing that already credits him, plus 1950 and
   1963. One record edit, recovering the evidence from #287 before it is closed.

4. **Make `merge-run.js` append a routine-log shard, or drop `daily-merge` from the roster.** Today it
   ran, merged a PR, and reported DID NOT RUN; the row is now uninformative every single day.
   *(Second day.)*

5. **Make `daily-report.js` read shards from open routine branches, not just `main`.** It already
   lists the open PRs, so it can read each branch's shard; today it called two healthy routines dead.
   *(Fourth day.)*

6. **Sweep `schema.creator.sameAs` off the 77 `Unknown` creators — the 23 pointing at a person's
   entity page first.** Each currently tells a machine reader that the unknown speaker *is* the person
   the page exists to exonerate. Its own commit, as #295 asked.

7. **Suppress the `reports-close` alarm until its 12:00 slot has passed.** Compare `when` to the
   current time before marking a daily routine missing. *(Fourth day.)*

8. **Make harvest dedup variant-aware, or drop the queued Sun Tzu candidate now.** "Keep your friends
   close, **but** your enemies closer" is still `queued` while the comma-and form is `ingested`, so it
   costs a selection slot every morning. *(Second day.)*

9. **Fix `prep-wave.js --credited` to stamp on an explicit flag rather than an author-name
   difference.** It cannot stamp the misattribution class this site is built around — a famous
   credited name with an unknown true author. *(Second day.)*

10. **Judge the 2026-07-29 report-gate run so the ladder can move.**
    `node tools/report-gate.js --judge agree|disagree` after reviewing the six `would-pr` records in
    `data/report-queue.json`. *(Fourth day.)*

11. **Write down the loc.gov convention — cite without a link, per #295 — so the next wave does not
    re-decide it.** One paragraph in the wave doc; the browser spot-check that item 7 asked for
    yesterday is moot for the page that shipped.
