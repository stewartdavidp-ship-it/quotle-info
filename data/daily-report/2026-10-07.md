`daily-reports` (#1096) did the thing this ledger has been asking for six days, and its finding is

> **"the doc's closing claim — 'something leaves the container detached with a stale `main`, and

Its evidence is a reflog with exactly **one** entry before its own recovery:

fd44258c5 main@{2026-10-07 08:05:07}: merge origin/main: Fast-forward   ← its recovery
831b7c211 main@{2026-10-06 07:15:11}: branch: Created from refs/remotes/origin/main

> **"So nothing in any session detaches anything. The local `main` ref was written once, when the
> container image was built (2026-10-06 07:15 UTC, ~25h before this run), and has been frozen at
> `831b7c211` ever since."**

**This report's container corroborates it independently.** Its own reflog, read first-hand:

```
bb6f86b50 main@{2026-10-07 12:04:16}: merge origin/main: Fast-forward   ← this run's recovery
831b7c211 main@{2026-10-06 07:15:11}: branch: Created from refs/remotes/origin/main
```

**The same SHA, to the same second, in a container started four hours later.** Two containers, one
frozen ref. The drift differed only because commits had landed in between — **8 commits behind at
08:05, 11 behind at 12:04** — which is exactly what a frozen ref predicts and which explains the
variation that has been looking like a pattern to find: *"8 today, 37 on 2026-10-05, 28 and 31 on
2026-08-16."*

Three consequences:

- Exception (b) will fire **every day, in every containerised run**. It is not a glitch. Yesterday's
  report recorded a container whose ref was *current*; on that evidence the two halves looked
  separable. They are not separable in general — that container was simply running on a freshly baked
  image.
- The remedy is an **image/startup fix**, not a repo fix: bake no local `main`, or fast-forward it on
  container start. Correctly reported and not touched — the pass may not edit `workflows/`.
- `workflows/DAILY-REPORT.md` Step 0 (and the same paragraph in the other routine docs) still tells
  the reader the cause is unknown and worth hunting. **That text is now false** and will cost whoever
  reads it next a wasted investigation. Proposal 2 covers both halves.

`daily-review` (#1097) hit the same condition in a third shape — *"the container started with HEAD on
a `claude/…` branch that was level with `origin/main`, while the local `main` ref sat 8 commits
behind"* — attached rather than detached, same frozen ref. Consistent with the image theory, and the
reason proposal 2 should fix the ref rather than the detachment.
