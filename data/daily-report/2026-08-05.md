## Findings

### 1. The merge pass ran **four** times today; the census can see one — and three shards are stranded on a branch with no PR

`merge.yml` fired at 02:28, 05:45, 08:35 and 11:20 UTC, all `success`. Only the 08:35 pass appears in
the routine census, because only its log shard reached `main`.

The 11:20 pass merged #348 and #349 and wrote its shard — commit `e95d8c988` — to
`origin/merge/2026-08-05`, where it still sits **with no pull request**. The cause is in
`.github/workflows/merge.yml`'s "Open a log PR for this pass" step:

```
gh pr view "$BRANCH" --json number >/dev/null 2>&1 || gh pr create ...
```

`gh pr view` matches a **merged** PR just as happily as an open one. Once the day's first shard PR
merges — #348 did, at 11:21 — every later pass on the same day pushes its shard to the same branch,
finds #348, and skips creating a PR. `origin/merge/2026-08-04` carries the same wreckage: **three**
shards from 08-04 (08:36, 11:23, 22:11 UTC) that never reached `main`.

**This is not cosmetic. It already produced a wrong proposal.** Yesterday's item 11 — *"Run
`merge.yml` hourly instead of daily. Today it ran once"* — was written against the same undercount.
`merge.yml` has been on `0 */3 * * *` (eight passes a day) since before that report; it ran **eight**
times on 08-04. The census said one, so the report proposed a change that was already made.

### 2. Both open PRs are `HUMAN` at the gate and no routine will ever merge them

```
HUMAN    #317   claude/recursing-kare-522d2b     branch is not a known routine prefix — left alone
HUMAN    #345   fix/template-schema-passthrough  branch is not a known routine prefix — left alone
```

`merge-gate.js` allowlists `wave-`, `reports/`, `review/`, `discovery/`, `merge/`, `report/` and
fails closed to `HUMAN` on anything else. Both PRs are `CLEAN` and green; they are simply invisible
to every merge authority in the system.

This is a structural trap for exactly the class of work the waves are told to produce.
`workflows/README.md` § step 5 tells a wave to put generator findings **on their own branch** — #345
says so in its first line: *"Own branch, not merely own commit: `merge-gate.js` judges files, so a
`wave-` branch touching `tools/` makes the whole wave a scope escape."* The wave obeys the doc, and
the resulting PR can then only ever be merged by hand. #317 has been open since 2026-08-03.
