### 5.2 The generator cannot emit the field that would have prevented the wave's one high finding

The `cool-papa…` record's `Quotation.disambiguatingDescription` *"fell through to the generic
`attributed` default: 'not traced to a primary source.'"* The visible prose cites two — Paige using

this same wave, sourced to a 1958 newspaper, renders 'Attribution traced to a primary source.'"* So
the template does not consider a newspaper disqualifying; the default simply did not know.

It was fixed by setting `schema.verdictNote`, *"the record override `tools/template.js` already
supports"* — and then the wave reported the general case rather than reaching for it:

> *"`DOSSIER_SCHEMA` cannot emit `schema.verdictNote`, so an `attributed` record whose evidence is
> genuinely unsettled always ships a verdict note contradicting its own prose until a fix stage
> catches it. That is the same shape as the `misattribution.items[].kind` case and may deserve the
> same treatment — derive it in `toRecord` rather than spend schema bytes."*

**A corpus measurement this report ran, to size it:** `main` holds **267 `attributed` records, of
which 32 carry a hand-set `schema.verdictNote`** — so **235 ride the generic default**. That is not
235 defects: the default is correct wherever attribution genuinely is untraced. It is the population
in which this defect can only be caught by an audit reading the prose, one record at a time, which is
exactly what happened today.

The proposed remedy is notable for **sidestepping item 59**: deriving the note in `toRecord` spends
no `SCHEMA_BUDGET` bytes, so unlike item 74 it is not queued behind the 4,072-byte ceiling. Item
**93**, new today.
