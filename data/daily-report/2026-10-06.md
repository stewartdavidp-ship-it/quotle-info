### 5.6 Item 108's mechanism is narrower than this ledger has been stating

Preflight failed on `git on main` **alone**, with `local main sane`, `tree clean` and `current with
origin/main` all passing — documented exception (b), applied exactly as printed. But:

```
git merge --ff-only origin/main  →  Already up to date.
git reflog main  →  831b7c211 main@{0}: branch: Created from refs/remotes/origin/main
```

**The local `main` ref was current, not stale.** The fast-forward discarded nothing and moved nothing;
the ref sits at `831b7c211`, which is `origin/main`'s tip. Yesterday four containers each had this ref
**37 commits behind**; today's is level.

left **detached**, always; the ref is **sometimes** stale. That matters for the remedy — a setup-script
`git checkout main` would have sufficed today, but the 37-commit cases need the `-B`, so the fix must
still be `git fetch origin main && git checkout -B main origin/main`. It also means exception (b)'s
own reasoning ("the start state is a stale local `main` ref behind a detached HEAD") describes the
common case, not today's. Nothing was at risk either way. Proposal 6.
