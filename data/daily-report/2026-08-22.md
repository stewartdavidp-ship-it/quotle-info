## 3. Findings

### F1 — `daily-review` reviewed nothing: one source's outage hard-stopped the whole pass

The pass recorded `error` and, in its own words:

> **preflight STOP: reach www.gutenberg.org failed** (timeout; direct probe returns HTTP 504 through a
> healthy, non-selective proxy — upstream outage, not an allowlist issue). Per DAILY-REVIEW.md step 0
> this is a hard STOP that is not mine to fix: **no scan.js, no records opened, no build.**

Its PR body rules out the cause preflight's own remedy text points at: *"`$HTTPS_PROXY/__agentproxy/status`
reports `"selective": false` with no recent relay failures, and the other three sources […] all reach
fine."* It also declined to patch the misleading remedy, correctly: *"a detector whose remedy text is
imprecise is a shared-generator defect: reported here, changed nowhere."*

**This is corroborated independently.** This morning's wave hit the same host and reached the same
conclusion by a different route: *"the CONNECT tunnel establishes and the origin answers `503`, with no
`x-deny-reason`, so by preflight's own stated criterion that is the origin answering rather than the
proxy refusing. It is a Project Gutenberg outage, not an egress block."*

So the check is right that Gutenberg is unavailable and wrong to treat that as a reason to stop. Its own
source comment says *"WHAT THIS CHECK IS ACTUALLY ASKING is 'can we reach the origin', NOT 'does the
origin like us'"* — but `head()` classifies a 12-second timeout as `blocked: true`, which is exactly what
a down-but-answering-slowly origin produces. **Second review pass lost to this check in three days**
(2026-08-20, 2026-08-22). Decision **1**.
