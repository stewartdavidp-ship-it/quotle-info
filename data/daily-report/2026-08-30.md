### 5.2 The prefix stripper cannot catch these, and must not be widened to try

`tools/qi-harvest.js:129` — the fix landed on 2026-08-27 as #685, *"match QI's title prefix by shape,
not by whitelist"*:

```js
const KIND_RE = /^([A-Z][A-Za-z]*(?:\s+[A-Z][A-Za-z]*){0,2})\s+Origin:\s*/;
```

It requires the literal word **` Origin:`**. It correctly strips *"Quote Origin:"*, *"Quiz Question
Origin:"* and the other 29 kinds. It cannot match *"Taxes:"* or *"Beatles Rejection:"* — QI's bare
topic-prefix title shape — because there is no `Origin` token to anchor on. Both records reached the
queue through that gap.

**The obvious widening — strip any leading `Word:` — would corrupt four genuine records**, all
currently `verified`, all of which legitimately open with a colon:

```
read-my-lips-no-new-taxes                          "Read my lips: no new taxes"
i-like-work-it-fascinates-me-…                     "I like work: it fascinates me…"
puritanism-the-haunting-fear-that-someone-…        "Puritanism: The haunting fear that someone…"
that-is-happiness-to-be-dissolved-into-something-… "That is happiness: to be dissolved into…"
```

So this is a judgement call about two specific candidates, not a regex tune. That is why it is a
decision and not something a routine should have quietly picked either way.
