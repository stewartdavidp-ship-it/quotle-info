### F3 — A Schema.org RULE breach reached the build and only an audit agent caught it

Both Thích Nhất Hạnh records carried a **blocker** with a silent knock-on:

> The name was entity-encoded `H&aacute;nh` → "Hánh". The correct "Hạnh" uses *a with dot below*,
> which **has no HTML entity**, so house entity style cannot express it. Because
> `plain(answer.authorName)` then no longer equalled `schema.creator.name`, `creatorOk` failed and
> `Quotation.creator` was **suppressed entirely** — breaching the standing Schema.org RULE that every
> quote page carry a creator with name and birthDate.

Two separate defects sit inside that. The first is editorial: the house entity-encoding convention has
no way to write a character outside the named-entity table, and degrading to the nearest entity
produces a **misspelt author name**. The wave's fix — literal Unicode for Vietnamese text — is
almost certainly the right convention, but it is currently one wave's local decision, not a rule.

The second is structural and worse: **a suppressed `creator` is silent.** `validate-records`, `build`
and `scan` all passed on these records; 51 corpus invariants reconciled; `scan` flagged 0. The RULE
breach was found by an audit agent reading rendered JSON-LD. Nothing mechanical would have caught it.

The same mis-encoded diacritic produced the wave's other blocker — the Wikiquote URL was
percent-encoded `%E1%BA%A1t` ("Nhạt") instead of `%E1%BA%A5t` ("Nhất") and **returned 404**, on the
page where that link *"carries the independent corroboration of the wording."* Both were corrected and
re-fetched at 200 before ship.
