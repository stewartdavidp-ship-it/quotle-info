### 5.2 New item 79 — the `mis-kind.js` gap is two tags, and the wave's fix landed on the second

The wave reported this rather than fixing it (a `wave-` branch may not touch `tools/`):

> "`tools/mis-kind.js` returns no `kind` for the tag **"Unconfirmed"**, and `template.js` defaults a

**Confirmed, and it is wider than reported.** I ran `kindForTag` directly against the module:

```

"Earliest located"   -> ""          (falls through → burgundy ✕ "refuted")

The second line is the one to notice. Audit finding **F7** changed the tag on

the page makes elsewhere. The wording change is right — 1959 is the earliest printing *located*, and
Chronicling America's coverage ends in 1963 — but it swapped a tag the list knows for one it does not.

**Nothing shipped broken.** I read both records off the branch: every affected row carries a hand-set
`kind: "context"`, so both render the neutral tilde as intended.

```

i-believe-in-the-sun…              {"tag":"Earliest located","kind":"context"}  ← F7's, incidentally

So this is a latent defect, not a live one: the **next** record to use either tag without a hand-set
`kind` gets the refutation marker. That is the seventh consecutive wave to hand-stamp `kind` because
